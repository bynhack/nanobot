# Case Audit Pending Fixes

目标：记录当前“涉诈资金审计”独立功能仍待补齐的问题、风险和开放决策。

## P2

### 全局 UI 基础控件可继续组件化

现状：

- 通用弹窗已经抽为 `Modal`。
- 业务源码中的下拉已经统一替换为通用 `Select`，包括案件上图、涉诈资金审计、图谱弹窗和设置页。
- `Select` 菜单已经改为页面级浮层，避免被弹窗正文、滚动容器或窄表单列裁切；选项文字支持按内容展开和换行。
- 审计页内次级按钮已收敛为局部复用组件。
- 项目里仍存在局部按钮样式、表单区块和提示条样式。

后续需要：

- 对按钮、提示条、表单区块做全项目层面的设计系统升级。
- 新增审计弹窗或表单时，优先复用 `Modal`、`Select` 和现有审计按钮结构。

定位：

- [select.tsx](../../frontend/src/components/ui/select.tsx)
- [modal.tsx](../../frontend/src/components/ui/modal.tsx)
- [page.tsx](../../frontend/src/case-audit/page.tsx)
- [workbench.tsx](../../frontend/src/case-graph/workbench.tsx)

### 嫌疑人金额认定卡片操作区需要保持克制

现状：

- “追踪下级资金”是卡片上的次级动作，已收敛为紧凑行内按钮，避免抢过金额信息。
- 结果列表已固定为按内容高度排列，单个嫌疑人时卡片不会被右侧面板剩余高度拉伸。

后续需要：

- 如果后续增加“查看证据”“加入嫌疑人”等动作，应形成统一的卡片动作区，不要把按钮做成大面积主操作。

定位：

- [page.tsx](../../frontend/src/case-audit/page.tsx)
- [styles.css](../../frontend/src/styles.css)

### 证据明细仍需补正式审计报告模板

现状：

- 证据明细已经展示原始流水、资金池变化和审计处理状态。
- 表格已经区分“进入认定链”和“保留底稿”，未命中的流水不会被隐藏。
- 证据明细已经生成稳定证据编号，并支持导出 CSV。

后续需要：

- 对齐办案人员提交审计部门时需要的正式报告版式。
- 增加可直接提交或归档的审计报告模板。

定位：

- [page.tsx](../../frontend/src/case-audit/page.tsx)
- [service.py](../../src/nanobot_channel_webui/case_audit/service.py)

### 档案管理仍可增强批量整理能力

现状：

- 从已认定嫌疑人点击“追踪下级资金”时，会复用同一来源对象、来源金额和层级的既有档案，不再重复创建同名档案。
- 档案下拉已经展示第几层追踪、上一层认定带入和执行状态。

后续需要：

- 后续可增加档案删除、归档、重命名校验和重复档案合并工具。
