# 会话级工作空间设计

## 1. 背景

当前 `nanobot` 的会话（session）已经具备以下基础能力：

- 会话消息本地持久化。
- 消息附件可通过签名 URL 暴露给 WebUI。
- WebUI 已具备文件预览能力。

但系统还缺少一个明确的「会话工作空间」概念。用户在一次对话中要求 agent 生成并交付的文件，当前可能散落在不同目录，缺少统一归档入口，也无法在当前会话中稳定查看这些最终交付物。

本设计引入「每个会话一个固定工作空间」模型，用于收纳该会话中最终交付给用户的文件，并在 WebUI 中提供查看与预览入口。

## 2. 目标

本功能的目标是：

1. 为每个聊天会话分配一个固定工作空间。
2. 仅收录「最终生成并发给用户的文件」。
3. 在 WebUI 中提供「查看工作空间」入口。
4. 支持在工作空间内查看文件列表并点击预览。
5. 复用现有文件预览能力，不重复建设预览链路。

## 3. 非目标

本期明确不做以下事情：

- 不追踪 agent 读取过但未交付的文件。
- 不追踪中间产物、临时文件、脚本或引用文件。
- 不把整个项目目录映射成工作空间。
- 不引入「每轮对话一个子目录」或「任务树」模型。
- 不在本期新增复杂的在线 Office 解析能力；如现有预览已支持则直接复用，否则保持现状。

## 4. 核心定义

### 4.1 会话工作空间

会话工作空间是一个与 session 一一对应的稳定目录，用于保存该会话中最终交付给用户的文件快照。

定义如下：

- 一个 session 对应一个固定工作空间目录。
- 一个文件只有在「明确作为最终结果发给用户」时，才会进入该工作空间。
- 工作空间中的文件应是可稳定回放的交付快照，而不是对原路径的脆弱引用。

### 4.2 最终交付文件

本设计中，「最终交付文件」限定为：

- assistant 当前会话最终回复中附带给用户的文件。
- `message` 工具向当前会话发送给用户的附件文件。

以下内容不算最终交付文件：

- agent 在执行过程中读写但未发送给用户的文件。
- 仅在文本中提及的路径。
- 中间生成后又被覆盖、替换或未对用户展示的文件。

## 5. 用户体验

### 5.1 用户视角

对于任意一个聊天会话，用户可以：

1. 正常与 agent 对话。
2. 当 agent 交付文件后，在当前会话看到「查看工作空间」入口。
3. 打开工作空间面板，查看该会话的全部最终交付文件。
4. 点击某个文件，直接使用现有预览能力进行预览。

### 5.2 产品语义

工作空间在产品上表达为：

> 这个会话产出的最终交付文件集合。

它不是项目目录浏览器，也不是 agent 的全部执行痕迹，只是用户真正收到的产物集合。

## 6. 方案选择

本设计采用以下组合方案：

- 产品语义：交付物工作空间。
- 存储模型：每个 session 一个真实目录。
- 收录时机：仅在最终交付给用户时登记。
- 文件策略：交付时复制或落盘到会话工作空间，形成稳定快照。
- 展示方式：读取工作空间清单，在 WebUI 中复用现有预览能力。

选择原因：

1. 语义清晰，和用户心智一致。
2. 可避免把中间文件误纳入工作空间。
3. 真实目录比纯索引更适合后续导出、清理和运维。
4. 快照式存储比引用原路径更稳定。

## 7. 存储设计

### 7.1 目录结构

建议新增运行时目录：

```text
<runtime-data>/session_workspaces/
  <safe-session-key>/
    manifest.json
    files/
      <stored-file-1>
      <stored-file-2>
```

说明：

- `<runtime-data>` 复用当前实例级运行时目录约定。
- `<safe-session-key>` 由 session key 安全转换得到。
- `manifest.json` 用于记录文件元数据。
- `files/` 存放该会话最终交付文件的稳定副本。

### 7.2 Manifest 数据

建议 `manifest.json` 结构包含：

- `session_key`
- `workspace_id`
- `created_at`
- `updated_at`
- `files`

每个文件条目建议包含：

- `id`
- `original_name`
- `stored_name`
- `stored_path`
- `source_path`
- `mime_type`
- `kind`（`image` / `video` / `file` / `text` / `pdf` 等）
- `size`
- `created_at`
- `message_id` 或关联消息标识

该清单仅作为展示与检索索引，不替代真实文件存储。

## 8. 后端行为设计

### 8.1 工作空间创建时机

工作空间目录按需创建：

- session 创建时不强制创建目录。
- 当该 session 第一次产生最终交付文件时，再初始化工作空间目录与 `manifest.json`。

这样可以避免为大量空会话创建无意义目录。

### 8.2 文件入工作空间时机

仅在以下时机执行登记：

1. assistant 最终回复附带文件给当前会话用户时。
2. `message` 工具向当前会话发送附件时。

登记流程建议为：

1. 校验文件存在且可读。
2. 生成安全存储名，避免同名覆盖。
3. 将文件复制到会话工作空间的 `files/` 目录。
4. 写入或更新 `manifest.json`。
5. 为 WebUI 返回可用于列表和预览的文件元信息。

### 8.3 为什么选择复制而不是引用

本设计要求在交付时复制文件到工作空间，而不是只保存原始路径，原因如下：

- 原始文件可能位于临时目录或用户工作目录，后续会被改写或删除。
- 工作空间应代表一次会话交付物的稳定快照。
- 复制后更便于权限控制、清理策略和历史回放。

### 8.4 安全约束

需要保证：

- 工作空间文件只能从合法 session 入口访问。
- 文件列表接口不能暴露任意本地路径。
- 预览与下载继续沿用签名 URL 或等价安全机制。
- 文件名展示可保留原始名称，但内部存储名应做安全处理。

## 9. 后端接口设计

建议补充以下接口：

### 9.1 获取会话工作空间

`GET /api/sessions/:key/workspace`

返回：

- 工作空间基本信息。
- 文件总数。
- 文件列表。
- 每个文件的预览或下载地址。

### 9.2 获取单个工作空间文件

若现有签名文件访问能力可直接复用，则无需新增独立文件流接口；列表接口可直接返回签名 URL。

如果现有链路不适合复用，再补：

`GET /api/sessions/:key/workspace/files/:file_id`

该接口职责仅为鉴权、解析和文件流转发。

### 9.3 会话列表中的摘要信息

本期可选地在 session 摘要中增加：

- `workspace_file_count`

用于前端决定是否展示明显入口或角标，但这不是必需项。

## 10. 前端设计

### 10.1 入口位置

建议在当前会话界面增加一个轻量入口：

- 标题栏中的「查看工作空间」按钮。

显示规则：

- 当当前会话没有工作空间文件时，可隐藏或置灰。
- 当存在工作空间文件时，显示按钮并可打开面板。

### 10.2 面板形态

建议使用右侧抽屉或侧板，而不是单独跳转页面。

原因：

- 不打断当前聊天上下文。
- 适合快速查看、预览和返回。
- 与现有聊天界面更容易整合。

### 10.3 文件列表项

每个文件项建议展示：

- 文件图标
- 文件名
- 生成时间
- 文件大小
- 文件类型

可选展示：

- 来源消息时间
- 最近预览时间

### 10.4 预览行为

本项目已有文件预览能力，因此本期不新增新的预览体系，直接复用现有预览能力。

前端只需要：

1. 从工作空间接口获取文件列表和可访问 URL。
2. 将点击行为接到现有预览组件或预览流程。
3. 对不可在线预览类型保持现有降级方式。

## 11. 与现有系统的衔接点

### 11.1 Session 系统

工作空间与现有 `SessionManager` 关联，但不应把工作空间元数据直接混入消息正文。

建议保持：

- session 仍负责消息历史。
- workspace 负责最终交付文件索引与存储。

可以在 session 元数据中挂极少量摘要信息，例如工作空间目录是否已初始化、文件数等，但不要把完整文件清单塞进 session JSONL。

### 11.2 附件发送链路

当前系统已有附件发送和签名 URL 暴露链路。会话工作空间应优先复用该链路，而不是重写一套预览协议。

新增逻辑应放在「最终附件发送」附近，职责是：

- 识别当前附件是否属于最终交付。
- 将其复制到工作空间。
- 为该工作空间文件建立元数据记录。

### 11.3 WebUI

WebUI 已能预览文件，因此本功能的前端重点不是预览实现，而是：

- 增加工作空间入口。
- 拉取工作空间文件列表。
- 调用现有预览能力。

## 12. 错误处理

需要覆盖以下情况：

1. 原始文件不存在：
   - 不写入工作空间。
   - 返回可观测日志。
   - 不影响主消息发送以外的行为判断，具体以发送链路现有容错策略为准。

2. 复制失败：
   - 不写入 manifest。
   - 记录错误日志。
   - 前端不显示该文件。

3. Manifest 损坏：
   - 可尝试从目录内容恢复最小可用列表，或返回空列表并记录日志。
   - 不应影响整个 session 的聊天功能。

4. 预览地址失效：
   - 前端展示降级态。
   - 用户仍可尝试重新打开或下载。

## 13. 测试策略

### 13.1 后端测试

需要覆盖：

1. 同一会话多次交付文件，均进入同一工作空间。
2. 不同会话文件隔离。
3. 非最终交付文件不会进入工作空间。
4. 同名文件不会互相覆盖。
5. 文件列表接口只返回当前会话合法数据。
6. 文件元数据与实际存储一致。

### 13.2 前端测试

需要覆盖：

1. 有工作空间文件时展示入口。
2. 无工作空间文件时入口隐藏或置灰。
3. 打开工作空间后可正确渲染文件列表。
4. 点击文件可进入现有预览链路。
5. 文件列表加载失败时有合理降级提示。

## 14. 分期建议

### 第一期

实现最小闭环：

- 每个 session 一个真实工作空间目录。
- 只收录最终交付给用户的文件。
- 提供工作空间列表接口。
- WebUI 增加查看入口和文件列表。
- 点击文件复用现有预览能力。

### 第二期（可选）

后续可考虑：

- 会话列表显示工作空间文件数。
- 支持工作空间内搜索、排序、筛选。
- 支持导出整个工作空间。
- 支持删除单个工作空间文件或清空工作空间。

## 15. 决策结论

本功能采用以下最终方案：

1. 一个聊天会话对应一个固定工作空间。
2. 工作空间只收录最终交付给用户的文件。
3. 文件在交付时复制为工作空间快照。
4. WebUI 通过「查看工作空间」入口展示文件列表。
5. 文件预览复用现有能力，不重复建设预览系统。

该方案与当前架构兼容度高，产品语义稳定，且能在较小实现范围内交付清晰可用的用户价值。
